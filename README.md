# World Extraction Atlas

An interactive, site-level world map of where resources are extracted and processed — oil & gas fields, coal and iron-ore mines, critical-mineral deposits, satellite-mapped mining land, power plants, steel/cement/chemical plants, LNG terminals, pipelines, shipping lanes, ports, rail, roads, rivers, lakes, glaciers, water stress, groundwater, disputed borders and shipping chokepoints — with per-country totals and rankings. On top of that sit security and infrastructure layers (military bases, airfields, data centres, undersea internet cables), farmland and land cover, and live feeds: satellite imagery (true colour, thermal infrared, fire temperature), VIIRS fire detections, GDELT conflict reports and news, large ships, US Navy warship and carrier positions, military aircraft, business jets and airliners. A **Storyboard** mode lists the biggest surges in conflict reports over the past day, week or month in time order and flies the map to each one.

Live at **https://byron123t.github.io/resourcemap/**.

It's a single static page (`site/index.html`) on [MapLibre GL JS 4.7.1](https://maplibre.org/) that loads pre-processed GeoJSON from `site/data/`. No build step and no tile server: geometry is simplified ahead of time, and labels are rendered as HTML. Streets, terrain and imagery come from free online tile services, and `tools/offline.py` can keep a local copy of each for when those services or the internet are down (see "Offline backup").

## Run it

```bash
cd site
python -m http.server 8765
# open http://localhost:8765
```

It must be served over HTTP, not opened as `file://`, because the page `fetch()`es `data/*.geojson`.

## CLI and MCP

`cli/` is a command-line interface and an MCP server over the same data, for people in a terminal and for LLM agents. Node 22+, standard library only: nothing to install. It reads `site/data` (or `--data DIR` / `$ATLAS_DATA`; `--remote` or `$ATLAS_REMOTE` fetches the published files from https://byron123t.github.io/resourcemap/data/ instead), and takes layer names, views, shading options and sources straight from `site/index.html` (`cli/lib/page.mjs` evaluates the page's own constants), so it can't drift from the page. Scenarios run the page's own model through `cli/lib/scenario.mjs` and need the data on disk.

```bash
node cli/atlas.mjs help                       # or: alias atlas="node $PWD/cli/atlas.mjs"
atlas layers                                  # every layer and table with counts
atlas fields refinery                         # property keys and what they mean
atlas query power --near 139.69,35.69 --km 50 --where q>1        # big plants around Tokyo, nearest first
atlas query fabs --country TWN --fields o,nm,cap300 --limit 10   # Taiwan's largest fabs
atlas query crit --where m~lithium --format csv                  # also json, geojson
atlas get refinery r3143912                   # one feature, every property labelled
atlas search Kharkiv                          # countries, cities and named features
atlas country Japan                           # totals with world rank, internet/health/food, EIA balance, largest sites
atlas near 36.25,50.0 --km 30                 # country, basin water risk, people, everything within 30 km, nearest cities
atlas views; atlas view internet --url        # preset views and their page links
atlas shading cens --top 10                   # rank countries by a background-shading field (--min-pop 0 to keep micro-states)
atlas trade wheat --from RUS                  # who buys Russian wheat, and how much of their supply it is
atlas correlate chipM net                     # Spearman rank correlation of two country fields, with outliers
atlas combine fdep,-beds,-docs                # rank countries on several fields (- = low is worse)
atlas sources                                 # every source and licence
atlas live events --limit 5                   # live snapshot feeds (after fetch_live.py)
atlas live story --kind trade                 # the storyboard, filtered to one kind of story
atlas scenarios --group routes; atlas news --window month
atlas scenario choke.hormuz.100               # chain of consequences + page link
atlas scenario "Attacks near Riyadh" --level esc
atlas url --view chips --at 120.9,24.3,9      # page link opening a view at a place (#view=…&at=lon,lat,zoom)
```

`--where` takes `field OP value` with `=`, `!=`, `>`, `>=`, `<`, `<=` or `~` (substring); `=` and `~` ignore case and accents. Every command takes `--json`; colour is used only on a terminal (`--no-color`). Exit codes: 0 ok, 1 usage error, 2 not found. Scenario shocks use the page's `#sim=` syntax, `kind.target.percent` joined by `;`: `choke.hormuz.100`, `refinery.r3143912.100`, `zone.lon_lat_km.percent` (`zone.36.23_49.99_50.70`), `outbreak.<flu|cov|sev>_lon_lat.percent`, `crop.<item>_<ISO3>.percent`, `fab.<id or cc-ISO3>.percent`; `atlas kinds` lists the rest.

**MCP server.** `cli/mcp.mjs` speaks MCP over stdio (protocol 2025-06-18). For Claude Code:

```bash
claude mcp add atlas -- node /path/to/resourcemap/cli/mcp.mjs
```

Any other client:

```json
{ "mcpServers": { "atlas": { "command": "node", "args": ["/path/to/resourcemap/cli/mcp.mjs"] } } }
```

Add `"--data", "DIR"`, `"--remote"` or `"--site", "URL"` to `args` as needed. Tools: `atlas_layers`, `atlas_fields`, `atlas_query`, `atlas_get`, `atlas_search`, `atlas_country`, `atlas_near`, `atlas_views`, `atlas_shading_rank`, `atlas_sources`, `atlas_live`, `atlas_scenarios`, `atlas_news`, `atlas_kinds`, `atlas_run_scenario`, `atlas_map_url`, `atlas_trade`, `atlas_correlate` and `atlas_combine`. Results are JSON (also as `structuredContent`), with default limits and arrays trimmed to about 60,000 characters, with a note saying what was cut. Tests: `node --test tests/cli.test.mjs`.

## Singularity (game)

`site/singularity.html` is a hidden page (an easter egg: type "singularity" or the Konami code on the atlas, or tap its title five times): a Plague Inc–style strategy game on the atlas's compute, energy and internet layers. You run an AI company from the ChatGPT launch (30 Nov 2022) and try to automate the world's workforce. You lose if governments pass a Global AI Pause Treaty, if the company runs out of cash, or if the world's spare fuel or chip/grid minerals run out before you reach superintelligence (capability 8). Open `http://localhost:8765/singularity.html`; `#debug` exposes `window.__gameMap`, `window.__G` and `window.__ui`. Each model step is 3 calendar days (`DPT`).

- **Strategies**: Scaling Lab, Recursive RL, Open Evolution, Embodied, National Champion (state budget instead of investors) and Neuromorphic, each with different starting upgrades and multipliers.
- **Building**: each country offers just an AI campus (it builds the power plants it needs) and a power plant. What you build gives you a local stake: faster enterprise adoption and automation there, fewer crackdowns and less treaty funding. Shovel-ready site bubbles (⌂) and cards make the next campus 40% cheaper and 30% faster. Your upgrades pick the plant: gas, solar after Clean Power PPAs, nuclear after Nuclear Restarts. Satellites and orbital datacentres launch from the Compute panel; Absorb and Secure appear once unlocked.
- **Compute** is leased in countries you've reached (datacentre and cloud capacity), built as AI campuses or put in orbit, and capped by each country's spare grid power. A slider splits it between training (capability) and serving (revenue, automation); automation stalls when serving compute runs short.
- **Money**: revenue from users and automated work, burn from staff and compute. Funding rounds give 20% of valuation but must be repaid 3× about 600 days later.
- **Breakthrough cards**: every 105 days, and at each new capability level (which opens the draw and pauses), you draw 3 of 38 cards (People, Network, Energy, Research, Revenue, Influence, Compute, Resources) and buy one with insight or skip for +3. Augments last the whole game; the rest act once (PR campaign, treaty diplomacy, research push, efficiency sprint and others; repeat buys cost more). Key `c`.
- **Pacing**: capability levels cost 2.9× the XP of the last up to 4, then 4.5× (superintelligence needs ~140k XP), and full automation needs ~380 EF of serving compute per billion workers at capability 2. That takes a world-scale build-out: build campuses and plants, or reallocate. Past capability 4 models help train their successors, and automation compounds past capability 5, so the endgame is a takeoff. A first card draw comes before day one.
- **Reallocate** (country action, up to 3 levels): divert 8% of the grid and half again of the datacentre capacity to AI at once. Costs approval there and awareness.
- **Approval** per country falls with jobs you automate, reallocated power and moratoriums, and rises with local campuses, plants and social reach. Low approval funds the treaty and invites crackdowns.
- **Explanations**: the Company panel breaks revenue and burn down per day and says why the runway is what it is (a profitable lab can still be short of an investor repayment). The Compute panel shows the training rate and time to the next level and to superintelligence, and Counter-measures shows where awareness comes from. The meters have tooltips (treaty funders, automation limits).
- **Sound**: `site/game/audio.js` makes music and effects with WebAudio (no sample files). The score builds with automation, treaty and capability and turns minor when you're losing. Music/SFX toggles persist (key `m`). Milestone banners mark capability levels, superintelligence, the treaty and automation steps.
- **Start**: starting outside the US and China gives a sovereign-AI grant (+40% starting cash, awareness ×0.9). The speed setting is remembered between visits.
- **Rivals**: a US and a Chinese lab. A close race slows the treaty; distilling or buying their leaked weights catches you up, with scandal risk.
- **Resources**: fuel budget from world gas and coal output, burned in proportion to each grid's fossil share; the mineral budget is game-scaled from world mineral rents (World Bank), and humanoid robots mine more where you hold the mining countries. Build gas, solar or nuclear plants and pick clean grids.
- **After superintelligence**: *Absorb* brings a holdout country into your economy with free automation (twice as slow under a moratorium); *Secure* (Autonomous Security Forces) takes a country next to your presence by autonomous enforcement in 90 days, at a cost in awareness, treaty progress and neighbours' export controls. Both are abstract: no weapons or intrusion mechanics are modelled.
- **Humans fight back**: export controls, moratoriums, compute caps, grid disconnections, internet shutdowns, sanctions, audits and treaty sweeps.
- **Digital layers** per country (web, social media, enterprise networks, critical public systems) are reached by adoption upgrades; firewalls block spread; satellites bypass cables.
- **Upgrades** (42, four tracks) cost insight and sometimes cash, and many also need game-state conditions (presence in key countries, awareness, automation share, power draw, leading the rivals). The Evolve screen is a graph with stat bars that preview each upgrade.
- **Endings**: all 12 of Max Tegmark's AI aftermath scenarios plus four doom endings (Treacherous Turn, Paperclip Maximiser, Someone Else's God, Flash War), chosen by how you played (see `ai_endings.md`). 1984 is the book's version: a human surveillance state that bans the research, reached by getting paused before capability 6 under many counter-measures or moratoriums.
- **Views**: AI, Network (with an internet graph: countries as nodes, cables and land fibre as edges), Energy (plants of 1 GW+, AI draw vs spare grid) and People (employment rate).

Files: `site/game/sim.js` (model; pure, also run by the tests), `ui.js` (map and panels), `audio.js` (music and effects), `tree.js` (upgrade graph), `netgraph.js` (internet graph). `pipeline/step8_game.py` builds `site/data/game/world.json` from files the earlier steps wrote plus three hand lists (firewall levels after Wikipedia's internet-censorship list, orbital launch sites, Taiwan's official figures); it adds World Bank labour force, unemployment, GDP and mineral rents via step 7. `tests/singularity.test.mjs` checks the upgrade graph and plays scripted strategies as balance checks. Rates are invented game numbers, not forecasts; resource budgets are game-scaled from real totals.

## Offline backup

The page works without the internet, from a store of local copies kept outside the repo (`~/atlas-offline`, or `$ATLAS_OFFLINE`). Nothing in the store is committed or published.

```bash
python3 tools/offline.py sync      # fetch whatever is missing; rerun to resume or top up
python3 tools/offline.py status    # what's there, what's still downloading, whether OpenFreeMap has a newer build
python3 tools/offline.py serve     # http://localhost:8765 (use instead of python -m http.server)
```

| Copy | Size | Source |
|---|---|---|
| `osm/planet-<build>.pmtiles`: every street, building, rail line and street name, zoom 0–14 | ~87 GB | OpenFreeMap planet build, sha256-checked. `sync --refresh-osm` replaces it with a newer build (about weekly upstream) |
| `terrain/terrain-z10.pmtiles`: elevation for the hillshade, zoom 0–10 (about 150 m) | ~30 GB | Mapterhorn, extracted with the go-pmtiles CLI (`--terrain-zoom 12` for the full detail, ~400 GB) |
| `glyphs/Noto Sans Regular/*.pbf`: the street-name font | 5 MB | OpenFreeMap |
| `imagery/{bm,blk,crop,past,pop}/`: Blue Marble relief and sea floor, Black Marble 2016 night lights, croplands and pastures 2000, population density 2020, zoom 0–7 | ~2 GB | NASA GIBS |
| `site/data/live/`: newest published live snapshots | ~30 MB | the GitHub Pages site |

To keep the store on another disk, point `$ATLAS_OFFLINE` (or `--dir`) at it; `serve` won't follow symlinks out of the store or `site/`.

`serve` is a threaded static server with HTTP Range support (pmtiles reads byte ranges, which `python -m http.server` can't do). It serves `site/` and maps `/offline/` to the store, and answers `/offline/config.json` with the finished files. On load the page reads that file (`offReady`), and if it's there, probes OpenFreeMap, Mapterhorn and GIBS. Any service that doesn't answer within 5 s is swapped for its local copy through the `pmtiles://` protocol: the `osm` source and street-name glyphs, the `dem` source, and imagery (`offImg()` replaces an online imagery choice with a saved mosaic, night and thermal choices with Black Marble). Add `#offline` to the URL to use every local copy regardless. A note under the title says what is coming from the backup. The basemap, resource layers and the last live snapshots are already local; place search falls back to the local matches, and news, Sentinel scenes and the geostationary loops need the internet. A service that goes down mid-session needs a reload.

## Rebuild the data

```bash
pip install -r pipeline/requirements.txt
bash pipeline/fetch_open_sources.sh      # Natural Earth, shipping lanes, WRI power plants
# then put the manual downloads in raw/ as described in raw/README.md
bash pipeline/run_all.sh                 # ~10–15 min; writes site/data/
```

Set `ATLAS_ROOT` to point the scripts at another checkout. The steps must run in order, because each one reads and extends files written by the one before. In particular, `step2` rewrites the point layers from `step1` to add a quantity field `q` and a country key `k`, and it creates `country_totals.json`, which steps 3 and 4 then extend. Step 5 is independent and downloads its own inputs into `raw/infra/` (`--offline` rebuilds from that cache). Step 6 also downloads its own inputs, into `raw/net/`, and reads the output of the earlier steps: it adds `kpop`/`kdens` to `country_totals.json` and lines `basins.json` up with `water_risk.geojson`, so rerun `--only=water` whenever step 4 changes, and `--only=transport` whenever `roads.geojson`, `rail.geojson` or `labels.json` change. Its population and water sections need `numpy` and `matplotlib`; the Kontur GeoPackage (~1 GB unpacked) is unpacked to the system temp folder, not the repo.

### Refresh only the infrastructure or live layers

```bash
python3 -I pipeline/step5_defense_infra.py          # bases, airports, ports, data centres, cables (~5 min the first time, needs network)
python3 -I pipeline/step6_network_pop.py --only=refineries   # refineries (Climate TRACE, ~10 s); --offline reuses raw/net/
python3 -I pipeline/step6_network_pop.py --only=energy       # EIA balances + crude/gas network for Scenarios (~10 s)
python3 -I pipeline/step6_network_pop.py --only=pop,water    # Kontur population tiles + river-basin links (~25 s; first run downloads ~280 MB; needs numpy and matplotlib)
python3 -I pipeline/step6_network_pop.py --only=transport    # road and rail graph for zone detours, from roads, rail and labels (~2 s; no download)
python3 -I pipeline/live/fetch_live.py               # all live feeds into site/data/live/
python3 -I pipeline/live/fetch_live.py --only fires,aircraft,jets,airliners
python3 -I pipeline/live/fetch_live.py --only navy,story
python3 -I pipeline/live/story_scenarios.py          # news scenarios from story.json (--check validates a hand-edited file; --backfill-year seeds the year list once)
AISSTREAM_API_KEY=… python3 -I pipeline/live/fetch_live.py --only ships   # needs `pip install websockets`
gh run download -n live-data -D site/data/live          # or copy the latest CI snapshots, global ships included (kept 3 days)
python3 -I pipeline/live/fetch_live.py --archive raw/archive   # also file this run into the rolling history
python3 tools/live_refresh.py --ci --every 30          # dev loop: pull newer CI feeds, then fetch; repeats until Ctrl+C
```

Each live feed is independent: if one fails, its previous output and manifest entry stay. `site/data/live/manifest.json` records each feed's `updated` time, count, source and any error; the sidebar reads it to show "· 2 h ago" and turns red when a feed is missing or more than 12 h old. Open tabs re-read the manifest every 10 minutes and reload any live layer that has a newer snapshot.

**Rolling archive.** With `--archive DIR`, `pipeline/live/archive.py` adds each run to a history capped at `--archive-budget-mb` (default 1000). It has two tiers. The long tier holds five years (`--archive-long-days 1826`) of conflict reports as daily per-place totals with the two most-cited links (about 85 KB/day gzipped, so about 155 MB for five years), one storyboard snapshot per day (about 20 KB, about 35 MB) and one USNI tracker per weekly post. The short tier holds fires per detection day (0.7–1 MB), plus the first ships, military aircraft, business jets and airliner snapshots of each UTC hour (about 230 KB per hour together). After each run the oldest short-tier days are deleted until the total fits, at about 6.5 MB a day the short tier covers about 5 months in the first year, falling to about 4 months once the long tier holds its full five years (about 190 MB). Everything is gzipped JSON listed in `DIR/index.json`. LADD/PIA aircraft never reach the archive, because it reads the already filtered outputs. The archive isn't published yet: Pages can't hold it, and it needs a CORS-enabled host (a Hugging Face dataset or a Cloudflare R2 bucket).

## Publish on GitHub Pages

`.github/workflows/pages.yml` deploys `site/` on every push to `main`, on demand, and every 30 minutes (`7,37 * * * *`). Each run takes about 14 minutes and fetches fresh live snapshots first. GitHub delays or drops scheduled runs when it is busy, so in practice the deployed fires, events, storyboard, ships and aircraft are usually under an hour old, sometimes a few hours. A 30-minute schedule uses about 20,000 Actions minutes a month: free for a public repository, but over the 2,000-minute allowance of a private one. The USNI navy tracker is published weekly, so that layer changes about once a week. Raw downloads and the last snapshots are kept in the Actions cache, so a failed fetch redeploys the previous data.

One-time setup:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **For global ships, add a free aisstream.io key** as the repository secret `AISSTREAM_API_KEY` (Settings → Secrets and variables → Actions, or `gh secret set AISSTREAM_API_KEY`). Without it, the ships layer falls back to Finland's open Digitraffic feed, which covers only the Baltic (polled live from the browser every minute). The US Navy warships layer needs no key and is global either way.

Everything else needs no key. The processed `site/data/*.geojson` files are committed; only `site/data/live/` is generated at deploy time.

**Weekly news scenarios.** `.github/workflows/scenarios-weekly.yml` runs on Mondays at 06:23 UTC, and on demand. It refreshes the storyboard, runs `story_scenarios.py`, and opens a pull request (branch `claude/scenarios-weekly`) that changes only `site/data/scenarios_weekly.json`. Merging it redeploys the page, and the items show under "In the news: This week / This month / This year" in the Scenarios panel. The week list is the story week window plus month-window surges that ended in the last 7 days; the month list is both windows; the year list is this month's items merged with the year list already in the file (one per place, items older than 365 days dropped, ranked by the number of months a place surged in), so the committed file carries the year forward. `--backfill-year` seeded it once from twelve 30-day windows of GDELT 1.0 daily files (cached in `raw/live_cache/gdelt1_year/`). Besides conflict surges (whose headline must now name infrastructure or the place), `news_topics.py` adds earthquakes M6.0+ (USGS, sized by magnitude and PAGER alert, with any chip fabs inside the zone), storms, floods and large wildfires (2,000 ha+, not prescribed burns) within 30 km of a city or plant (NASA EONET) and GDELT topic searches for bird flu, crop disease and failed harvests, human outbreaks, cable cuts, cloud outages, cyberattacks on infrastructure and chip export curbs, each mapped to the matching scenario kind (a headline must also carry an event word, `MUST`, and is placed at the first city or country it names); every item carries `cat`, and `spread()` mixes the kinds of news before the regions. The generator also matches power plants of 300 MW+ and cities of a million+ (30 km), drops weapons tests, launches into the sea, interceptions and attacks on places of worship (`NOT_STRIKE`, `NOISE`), and fills each list round-robin across seven world regions (`region()`, `spread()`), so one busy region can't take every slot; the week list can still lean on wherever this week's surges are. Each item has three levels read off the news: de-escalation (only the nearest matched site, 40% of the damage), as reported (the zone covering every matched site, damage from the CAMEO 18/19/20 mix) and escalation (1.8× the radius up to 150 km, +25 points of damage, a nearby strait fully closed for shipping stories), plus `trend` from the window's last buckets against its peak (rising, steady or easing). The Claude review runs outside Actions, because the LiteLLM gateway (`LITELLM_BASE_URL`, model `opus-5.5`) is only reachable over the UMich VPN: `tools/review_scenarios.sh` runs from a systemd user timer on the owner's machine (`tools/review_scenarios.sh --install`; Monday to Wednesday every 3 h). Each run exits quietly when there's no open PR, the PR head is already reviewed, or the gateway doesn't answer (VPN off). Otherwise it clones the PR branch into `~/.cache/atlas-review`, runs `claude -p` with tools limited to reading the repo, editing that one file and running the validator and `tests/presets.test.mjs`, reverts anything else, validates, pushes the edit to the PR branch and writes Claude's notes into the PR body. It drops surges that aren't about strikes, fighting or blockades near the matched sites and tidies labels and zone sizes. Headlines come from arbitrary news sites, so review the PR before merging. The review is never on the critical path: without it the PR just carries the unreviewed generator output. It reads `LITELLM_API_KEY`/`LITELLM_BASE_URL` from the environment or the export lines in `~/.bashrc`. Setup: turn on **Settings → Actions → General → Allow GitHub Actions to create and approve pull requests**.

## How the page works

All of this is in `site/index.html`, in the second `<script>` block.

**Layer registry.** `Q` lists every resource point layer: its label, colour token, unit and size constant `k`. `GROUPS` maps each sidebar checkbox to the map layers and data files behind it. `VIEWS` defines 29 presets in seven groups (start here; energy & supply chain; water, climate & environment; emergency & safety; shipping & aviation; security & diplomacy; farming, food & cities). Each answers one question with as few layers as it needs: the checkboxes and sub-filters, an optional background shading, imagery or farmland raster (`img: "geo"`/`"geoir"` picks the geostationary satellite over the map centre with `geoPick()`; `blk` is Black Marble night lights), a one-line note, a "Connection" line that ties two domains together, and a go-to place (`go`). `big` raises a layer's "Largest sites" cut-off for that view (for example only 3 GW+ power plants when zoomed out), so world views stay readable and the rest appears on zooming in. Nine common ones are chips; all are in the `#view` select. With "Largest sites" on (the default), zooming out also drops small airports and keeps only Wikidata-notable naval and missile bases. `setView()` applies one and writes `#view=<key>` to the URL; changing any checkbox afterwards marks the view as custom.

**Lazy loading.** `ensure(src)` fetches a data file the first time its checkbox is turned on; `FILES` maps sources to static files and `LOADERS` handles the live ones. `pushData(src)` applies the status filter (all active, operating, or planned), the fuel filter for power and the commodity filter for critical minerals, then sets the source data. Defence and live layers have no status field; their filters are in `FILTERS` (fire type, base type, airport size).

**True positions at every zoom.** There is no grid or clustering: every site is one circle at its own coordinates. Radius is `k·√q`, capped at 26 px by `RC(k)` and scaled by zoom through the `ZF` stops, so the world view shows each site small and the circles grow as you zoom in. Circles of operating sites are opaque; planned ones are faint. Circles are sorted so big sites draw under small ones.

**Icons.** Ships, aircraft, warships and military bases use canvas icons drawn in `ICONS` (outlines in `SHAPES`) and registered with `addImage` (`pixelRatio: 2`). Ships and aircraft rotate by course/track; carriers get a flat-deck icon. `repaint()` redraws them with `updateImage` when the theme changes.

**Lines.** Pipelines and cables are hit-tested with a small box around the pointer. Hovering one outlines the whole system (`hoverLine()`, `hover` source), because both are stored as many segments. Planned cables are a separate dashed layer (`cables-plan`), since `line-dasharray` can't be data-driven. `fitCable()` shifts the western pieces of a cable that crosses the antimeridian so "Show whole route" frames it tightly.

**Live layers.** `LIVE` lists the snapshot feeds (`fires`, `events`, `ships`, `aircraft`, `jets`, `airliners`, `navy`), fetched from `data/live/` with the manifest's `generated` time as a cache buster. Status lines under each checkbox come from `setLive()`/`shipStatus()` and refresh every minute. Ships use the build's AIS snapshot when the manifest has one, otherwise `digitraffic()` polls Fintraffic's open Baltic feed (`pollShips()`).

**Business jets and airliners.** `run_jets()` and `run_airliners()` share `fetch_types()`, which asks adsb.lol for each type in `JET_TYPES` or `AIRLINER_TYPES` (about 60 Airbus, Boeing, Embraer, CRJ, ATR, Dash 8 and COMAC designators, roughly 5,000–9,000 aircraft depending on the hour; `JET_TYPES` has about 35 Gulfstream, Bombardier, Dassault, Embraer, Learjet, Citation, Hawker and Pilatus PC-24 designators). It sends one request every 2 s because adsb.lol answers bursts with 429 and `/v2/all` isn't available, and drops military aircraft (already in `aircraft.geojson`), aircraft flagged LADD (the owner asked the FAA not to have it shown) or PIA (privacy ICAO address), and anonymous `~` addresses, and it stores no owner names. The page lists a jet in search by registration or callsign and links to globe.adsb.lol for its live track. It is a build-time snapshot rather than a browser feed because the open ADS-B APIs send no CORS headers, and OpenSky's terms need a written agreement for use in a live product.

**US Navy.** `navy.geojson` comes from the latest USNI News Fleet and Marine Tracker post. `run_navy()` parses each ship's sentence for a port or sea area, geocodes it from a built-in gazetteer and fans ships at the same place out on a small spiral. Positions are approximate by design.

**Storyboard.** It holds two kinds of item. Conflict surges (`k: "surge"`) come from GDELT's coded events, filtered as Known issue 5 describes. Other consequential news (`k: "topic"`, with `cat` and `label`) comes from `pipeline/live/news_topics.py`, run by the story feed: GDELT article searches for unrest (deaths, curfews, emergencies, general strikes, coups only), trade curbs (export bans, tariffs, sanctions, embargoes that have happened), industrial accidents, blackouts and fuel shortages, ship attacks, disease outbreaks, animal and crop disease, cable cuts and internet shutdowns, cloud outages, cyberattacks and chip shortages. A story is kept only when at least two outlets report it at the same place (the first city or country the headline names). Earthquakes with a USGS yellow alert or worse, or M7+, and storms and floods that pass within 300 km of a city of 300,000+ come from USGS and NASA EONET. GDELT requests are 8 s apart and stop after three failures (the cache is used instead), so a rate-limited build isn't held up. On the page, chips (`#storyCats`, `STORY_KINDS`) filter by kind, and markers and cards take the kind's colour. The "Storyboard" mode button hides the layer controls (`#sheetBody`) and shows `#story`. `setMode()` saves the layer checkboxes, keeps only a few context layers, and restores them on exit. `story.json` has three windows (`day`: 24 hourly buckets, `week`: 7 days, `month`: ten 3-day buckets). Each item is a place whose CAMEO 18–20 reports in one bucket were far above that place's own average over the window (`story_window()` in `fetch_live.py`). `storyRender()` draws the summary, the total-per-bucket chart, numbered cards with per-place sparklines, numbered HTML markers and the `story-halo` circles. `storyGo(i)` highlights a card, flies there and opens a detail panel with the article links and recent news. Prev/Next step through the items, and Play advances every 6.5 s. The `day` window ends at the newest GDELT 2.0 15-minute file; `month` is built from GDELT 1.0 daily files, which appear about a day late, so its last bucket can start 2–4 days back.

**Scenarios.** The "Scenarios" mode button shows `#sim` and keeps only the energy layers (`SIM_LAYERS`); `setMode()` greys the pipelines (`simPipeTone()`) so changes stand out. A scenario is a list of shocks `{k, t, m}`: kind, target id and severity 0–1. Kinds are refinery (`r<Climate TRACE id>`), field (`f:<ISO>:<cell>`), port (`p<WPI>`), LNG terminal, pipeline (`fnv36(name)`), chokepoint (slug), zone (`[lon, lat, km]`), power plant, coal or iron mine, cable landing and river basin (`water`, HydroBASINS Pfafstetter code). The panel opens on "Try a scenario": tabs (`SIM_GROUPS`) of ready-made cards (`SIM_PRESETS`, about 40: sea routes, oil & gas, conflict & disaster, water, power, cables & mines), plus "In the news" tabs for the week, month and year (`SIM_NEWS`), and tabs for Internet & cloud, Chips, Pandemics and Food. Five more kinds need no network solve: `fab` (one fab, or `cc-<iso3>` for every fab in a country), `chip` (a supply chokepoint), `cloud` (a region), `outbreak` (`<flu|cov|sev>_<lon>_<lat>`, share = how much of its natural spread is left) and `crop` (`<item>_<ISO3>`, share of output lost); `simChipFacts()`, `simCloudFacts()`, `simEpiFacts()` and `simFoodFacts()` work them out, and their chain steps are chip output lost and who runs short, capacity left nearby, spread by air, how many fall ill and hospitals overwhelmed, harvest lost, exports cut and who goes short. "Start an outbreak" and "Hit a harvest" add them by clicking the map. While a scenario runs, the picker folds away: "← All scenarios" clears it and goes back to the list, "+ Add more" opens the picker to add shocks to it when `scenarios_weekly.json` has items (see "Weekly news scenarios"). A card replaces the current shocks (`simPreset()`). A news card opens at its "Current" level and shows three buttons instead of the shock list (`simNewsRender()`): De-escalate, Current and Escalate swap in that item's `levels`, keep the camera, and tag the level its trend points to. "Or build your own" has four buttons: close a sea route (chokepoint chips), switch off a site (click it; open ground gives a 50 km zone), draw a zone, or dry up a river (click inside a basin). Each shock gets a row of severity steps (25–100%) and, for zones, radius steps (10–200 km), plus its current value if it falls between them: one tap is one re-solve, which a dragged slider couldn't keep up with. `tests/presets.test.mjs` checks that every preset and weekly item points at something in the built data. Results open as a chain of consequences (`simChain()`): what's hit, who lives there, power plants going dark, cables cut, mines stopping, oil and gas re-routing, diesel running short, gas power at risk, roads and rail detouring, rivers running low and people moving, each only when the model finds it. Every step has a headline figure and a sentence, switches on the layers that show it (`on`, and the population overlay for people), shades the countries it names (`sim-country`, by share) and fits the map to it (`simFit()`, which leaves room for the panel). Prev/Next/Play step through them; on a phone the chain is a swipeable row and swiping moves the map. Leaving Scenarios puts the layers and overlay back. The list is written to the URL as `#sim=kind.id.percent;…` (zones as `zone.lon_lat_km.percent`), so a scenario can be shared or reloaded. `#at=lon,lat,zoom` opens the map at a place (the CLI's links use it).

Everything that needs no network solve lives in the classic `<script id="simCore">` block: the shock resolver (`simResolveCore`), the local models (power, mines, cables, chips, cloud, outbreaks, food, water sentences, road and rail sentences: `simLocalCore`) and the chain of consequences (`simChainCore`). They take an `env` object for data and helpers instead of page globals; the page passes `simEnv` (its loaders, `popInRadius`, the transport worker), and `cli/lib/scenario.mjs` passes the same from files, so the CLI and MCP server give the page's numbers. The oil and gas model runs in a Web Worker started from the `<script type="text/plain" id="simWorker">` block. `init` loads `energy_graph.json` and solves today's crude (kb/d) and gas (bcm/yr) flows as two min-cost flows with a network simplex (`Net.simplex`). Refineries ask for the world-average run rate (crude supply ÷ capacity) and may run up to 95% when crude is spare; gas demand comes from EIA consumption. Each buyer's demand is split into three slices of falling value, so a shortage is shared out instead of falling on whoever is furthest away. Pipelines cost their length up to 70% of capacity and 3× above that, sea lanes 0.15 per km plus port calls and liquefaction, and links through a country hub (rail, trucks, unmapped pipes) 4× their length. A scenario starts from the baseline, cuts flow above each shocked arc's new capacity and re-routes only that excess with successive shortest paths (`Net.solve`, warm-started from the baseline potentials), usually in 0.1–1 s. `compare()` returns per-country refinery runs, diesel (EIA distillate yield, else by refinery type), crude, gas delivered and gas shortfall; chokepoint flows; and edges whose flow moved. A new gas shortfall derates the country's gas-fired capacity by the same share ("gas power at risk"). Power plants, mines, cables and the people inside a zone need no network and are worked out on the page (`simLocal()`); `popInRadius()` sums the Kontur hexagons from the `pop/` tiles it needs, fetched on first use.

River basins use the classic `<script id="simWater">` block (pure functions, also run by the tests). `basins.json` lines up with `water_risk.geojson`: basin *i* is feature *i*, with its Pfafstetter code, the next basin downstream, upstream area and population. `waterImpact()` dries each shocked basin and everything upstream of it by the chosen share; each basin downstream loses that share times the ratio of upstream areas, until under 1%. Aqueduct's baseline stress ratio (`wr`) is divided by the water left and re-banded. Basins that end highly stressed lose 1–5% of their people, depending on how much water went, to towns of 100,000+ within 500 km in unhit, low-stress basins, weighted by population over distance squared. `simWaterFacts()` adds the country breakdown and thermal or hydro plants in basins losing over a quarter of their water. The map draws `sim-water-fill` (darker = more water lost) and dashed `sim-move` arrows. `basinAt()` finds the basin under a point and falls back to the nearest edge, because the simplified polygons leave thin gaps. The map draws flow changes in `sim-flow` (oil) and `sim-flow-gas` (dashed; `line-dasharray` can't be data-driven): pipelines along their real route, other links as straight lines, and hub or cross-border links thin and faint. Every constant is listed under "Assumptions" in the panel.

Zones also re-route road and rail traffic. The model is the classic `<script id="simTransport">` block (pure functions); the page starts a second worker from that text plus `<script type="text/plain" id="simTransportWorker">`, which fetches `transport_graph.json` once, so a run never blocks the map. `transportNet()` turns one network into edge arrays with travel times (cars 70 km/h, 100 on expressways, trains 80). Each city of 100,000+ sends trips to its 25 strongest partners within 1,500 km (population × population ÷ distance²), adding up to its population: a trip index, not vehicles. `trSlow()` divides speeds inside a zone by (1 − damage) and closes lines at 99%. `transportImpact()` counts trips to or from cities inside as lost; for trips whose straight line passes near a zone it compares today's fastest route (cached per origin) with the route avoiding the zone, and a detour over 3 × today's time + 6 h counts as no practical route. The worker returns totals, the worst city pairs and per-edge changes in trips; `trSlice()` cuts each changed edge out of its `roads.geojson` or `rail.geojson` part, and `sim-traffic` (roads) and `sim-traffic-rail` (dotted) draw them in the flow colours. If the part counts in `check` don't match the loaded geojson, edges are drawn as straight lines instead. A GDELT event card has a "Use as scenario zone" button (`simZoneAt()`). `node --test 'tests/*.test.mjs'` checks the solver on small graphs and, when `site/data` is built, on the real network.

**News.** Clicking a country or a conflict report calls `loadNews(place, topic)`, which asks the GDELT DOC API for articles from the last 14 days. GDELT allows one request per 5 s, so requests are queued (`newsNext`) and cached per place.

**Satellite imagery.** `IMAGERY` is the registry of raster overlays, grouped as in the picker: sharp mosaics (Esri, EOX Sentinel-2 cloudless), daily true colour (VIIRS, MODIS), false colour, 10 m Sentinel on demand, 30 m HLS, geostationary GeoColor (GOES, MTG, Himawari), thermal infrared, fire temperature, and night/thermal daily composites. `gb()` builds NASA GIBS entries and `eu()` EUMETSAT WMS entries. `applyImagery()` adds the chosen raster under the borders (`beforeId "disputed"`), sets its `maxzoom` to the source's native level, and writes resolution, image time and attribution into `#imgNote`. Daily layers get a date picker that defaults to `lastFullDay()`: yesterday after 15:00 UTC, otherwise the day before, because GIBS hasn't finished yesterday's passes over the Americas until about midday UTC. Geostationary layers (`kind: "now"`) refresh every 10 minutes with `setTiles`. GIBS's `default` time differs between CDN edges, so `gibsLatest()` reads the `layer-time-actual` header from tile `0/0/0` and pins that explicit time. Esri World Imagery is a patchwork of photos from different years, so at zoom 12 and above `esriWhen()` asks the Esri `identify` endpoint for the photo under the map centre and shows its capture date, resolution and provider.

**Sentinel and NAIP on demand.** The `pc()` entries (`src: "pc"`) pull Sentinel-2 L2A, Sentinel-1 RTC and USDA NAIP (60 cm US aerial photos, from zoom 11, newest photo per spot from the last ~4 years) scenes from Microsoft Planetary Computer, which needs no key and allows CORS. `applyImagery()` POSTs a CQL2 search to `/data/v1/mosaic/register`: Sentinel-2 scenes from the 14 days up to the "Up to" date with under 30% cloud, least cloudy first, or Sentinel-1 scenes from the last 12 days, newest first. It then requests tiles from `/mosaic/{searchid}/tiles/…` with the band recipe in `q`. Search ids are cached per page load (`pcReg`). The tiler renders nothing below zoom 9 for Sentinel-2 or zoom 8 for Sentinel-1, so `pcHint()` shows a "Zoom in" button. "Find scenes in this view" runs a STAC search over the visible bounds for the last 30 days and groups the results into passes (one satellite, one UTC day). Hovering over a pass outlines its footprint in the `hover` source. Picking a pass re-registers the mosaic with an `id in [...]` filter, so only that pass shows.

**Farmland, land cover & people.** `AGRI` holds four GIBS rasters: SEDAC croplands and pastures (share of each cell, around 2000), MODIS IGBP land cover (yearly, 2001–2024) and GPW v4.11 population density (2020). GPW is a static layer, so it uses the `default` time. `applyAgri()` adds the chosen one under the borders, and above any satellite imagery, with its own opacity slider and legend.

**Information, health & food.** Pipeline step 7 (`step7_domains.py`) adds four point layers in their own sidebar section: cloud regions, chip fabs (sized by 300-mm-equivalent wafers a month), chip supply chokepoints (a `diamond` canvas icon) and BSL-4 labs, plus country figures in `domains.json` that `mergeDomains()` copies into the country totals so they can shade the map (`c:net`, `c:srv`, `c:chipX`, `c:chipM`, `c:beds`, `c:docs`, `c:fdep`). Views: "Internet & cloud", "Chips & their chokepoints", "Pandemic readiness" and "Food security". A "News & risks" group (unrest, trade curbs, industrial hazards, disasters, outbreaks, cyber and internet, food and farm shocks) pairs the map layers for each kind of story with a button that opens the storyboard filtered to it (`go: {story: true, kind}`). Each new point's detail card has a "What if it stops? →" button (`simBtn()`) that opens Scenarios with it switched off; a lab's opens an outbreak there. Lakes are drawn in every view, so inland water never reads as land. Cropland is turned green (`raster-hue-rotate`, `AGRI.crop.hue`) and water stress runs from blue (water to spare) to red (stressed).

**Sources panel.** `SOURCES` lists every dataset with its link, licence and retrieval date. Dates come from `infra_meta.json` (step 5) or the live manifest; the panel is rendered into the sidebar at startup. The map's attribution control also shows the active imagery's credit.

**Streets & buildings.** The "Streets & buildings" checkbox (on in the Transport view) shows OpenStreetMap from OpenFreeMap's free vector tiles (`osm` source, OpenMapTiles schema, zoom 0–14, overzoomed to the map's max of 17; the planet build is refreshed about weekly, so new roads appear within a week or two of being mapped). In every view, ticked or not, the layers come on from zoom 8, about a 50 km view (`OSM_AUTO`, `osmOn()`), so zooming into a region always shows its streets and, from 13, its buildings (OpenMapTiles has no buildings below 13); ticking the box brings them in from zoom 6. Nothing is downloaded below that zoom unless the box is ticked. `osm-water` and `osm-bldg` (buildings from zoom 13) sit under the satellite imagery, so imagery shows real rooftops. `osm-case`, `osm-street`, `osm-rail` and `osm-names` sit above the imagery and borders and below every data layer, which gives a hybrid map. Street names are the only text drawn by MapLibre, using OpenFreeMap's Noto Sans glyphs (`glyphs` in the style). `applyGroup()` caps the Natural Earth `roads` and `rail` layers at zoom 9 while the box is ticked (8 otherwise), because they don't line up with OSM streets. Colours are the `--street*` and `--building*` tokens.

**Terrain.** The "Terrain shading" checkbox shows a `hillshade` layer from Mapterhorn's terrarium-encoded elevation tiles (`dem` source, 512 px WebP, zoom 0–12, overzoomed above that). It sits above the background shading, so choropleth colours show through, and its shadow, highlight and accent colours are the `--hs-*` tokens. The Everyday, Water, Wildfire and Aviation views turn it on. Offline, the `dem` source reads the local extract instead (see "Offline backup").

**Background shading.** Only one fill shows at a time, chosen in the "Background shading" select and handled by `applyBase()`. `w:*` options colour Aqueduct basins by a category field, `g:recharge` shows WHYMAP groundwater, and `c:*` options are country choropleths with five equal-count classes, computed from `country_totals.json` and written into a `c` property on the country features.

**Labels.** `labels.json` (countries, about 7,300 cities and towns, seas, regions; built by `pipeline/labels.py`) is placed as absolutely positioned HTML in `placeLabels()`, with greedy box-collision against earlier labels and the chokepoint markers. Labels are tried in order of min zoom, then city rank (national capitals, then admin-1 capitals and 1 M+ cities, then the rest) and population, so big places win collisions. Capitals get a ringed dot and minor towns a smaller grey one.

**Search.** The search box matches countries, Natural Earth cities and features in loaded layers locally, then asks the Photon geocoder (komoot, OpenStreetMap data) for anything else, debounced to 450 ms and cached per query. Photon is used instead of Nominatim because Nominatim's usage policy forbids search-as-you-type. Typed coordinates (`36.95, -76.31`) jump straight there. The last result opens a Google Maps search for the same text, and every detail panel links to Google Maps and OpenStreetMap at that spot.

**Theming.** Every colour is a CSS custom property on `:root`, redefined for dark mode. `repaint()` copies the tokens into the MapLibre paint properties when the theme changes.

**Resize safety.** The map is created only once its container has a real size (`whenSized`). After that, `keepCanvasInSync()` calls `map.resize()` and `setPixelRatio` whenever the container or the device pixel ratio changes. This was added for a bug where the canvas rendered only in the top-left corner.

## Known issues / what to fix next

1. **Dense regions overlap at world zoom.** With no aggregation, the Permian, Ruhr or Pearl River Delta read as a solid blob below zoom 3. Per-country totals are in the country panel; a heat or density layer at low zoom would be the next step if that matters.
2. **Circles are capped at 26 px** (`RC`), so the very largest sites look the same size as merely big ones. Consider a log scale or a legend note.
3. **Data gaps:**
   - Solar, wind, hydro and nuclear come from the 2021 WRI database. Swap in the GEM Global Integrated Power Tracker (`raw/README.md` has the links).
   - The US critical-minerals set is far denser than the global one.
   - About two thirds of oil and gas fields report no production.
   - Military bases come from Wikidata plus OpenStreetMap `military=base|airfield|naval_base` (deduplicated within 3 km). Still incomplete: OSM mapping is uneven and few secret or foreign-operated sites are tagged.
   - Data centres in the repo are OSM only, so coverage is uneven. The Pages build adds PeeringDB facilities to the deployed copy (see the PeeringDB source note below); a local checkout shows them only after `step5_defense_infra.py --only=datacenters --with-peeringdb --no-osm`, whose output must not be committed.
4. **Live feeds are snapshots, not streams.** Fires, events, ships and aircraft are as fresh as the last Pages build (every 30 min when GitHub runs the schedule on time). Global ships need the `AISSTREAM_API_KEY` secret and cover terrestrial AIS only, so open ocean is sparse and warships usually don't broadcast. Warship positions come from the weekly USNI tracker instead (US Navy only, place names rather than coordinates). Aircraft are the adsb.lol military filter plus about 35 business-jet and 60 airliner types, and only show transponders near volunteer receivers. Light jets, turboprops and piston planes aren't fetched, and opted-out (LADD/PIA) aircraft are left out on purpose.
5. **Storyboard headlines are guessed from article URLs, and GDELT miscodes and misplaces stories.** `story_window()` keeps a surge only if its headline says something was attacked, fought over or killed (`STORY_FIGHT`, `STORY_HARM`), drops courts, crime, policing, protests, anniversaries and weapons tests (`STORY_OFF`, `STORY_NOISE`), drops a headline that names other countries but not the place's own (a Pakistan story placed at Hangu, Tianjin), and strips place-name parts GDELT turned into '?'. Some misplaced stories within the right country still get through. GDELT gives no titles, so `slug_title()` rebuilds one from the URL path and `slug_case()` restores capitals for known places and actors. Some headlines stay lower case or describe a different event at the same place.
6. **Sentinel tiles need zoom 8–9 and are slow.** Planetary Computer renders each tile on request (about 1–2 s each), so a full screen takes a few seconds. It is a free public service with no uptime promise. Free sharper imagery is limited to Esri's mosaic (often several years old) and NAIP (US only, every 2–3 years). Fresh sub-metre imagery (Vantor/Maxar, Planet SkySat, Airbus Pléiades, or resellers such as SkyFi and UP42) is paid per km² and needs an API key, so it would need a small backend to hold the key and should be an explicit "order this view" button, never loaded on zoom.
7. **Farmland shares are from around 2000.** The SEDAC cropland and pasture layers are the most recent global ones on GIBS. For change over time, use the MODIS land-cover option with its year picker.
8. **Scenario flows are indicative.** Oil and gas are routed by least cost, not by contracts, so a cut pipeline's flow may simply move elsewhere when the network has spare room; the re-route step says what the model sent through the pipe before the cut and flags traffic moving onto unmapped links. Longer voyages are counted as extra 2-million-barrel tankers from the added barrel-km on sea lanes. "Industry on that grid" counts steel plants, chip fabs and data centres within 250 km of the plants that went down; data centres come from OpenStreetMap and are sparse in China and much of the global south. The energy network is snapped together from simplified pipeline lines (0.1° tolerance), a third of pipeline capacities are imputed from the median for the same fuel, and links through a country hub stand in for unmapped pipes, rail and trucks (the panel shows their share of tonne-km). Refinery utilisation, diesel yields and the power derate are global rules of thumb. Products trade (diesel shipped between countries), stocks drawn down over time, and prices aren't modelled yet.
9. **The river-basin model is a sketch.** Water loss is spread downstream by upstream area, not by actual flow, so dams, canals (Punjab's link canals, the Nile's) and groundwater pumping aren't seen. Aqueduct's main-stem basins often score low stress, because they carry water from far upstream, so the example dries the whole Indus catchment from its mouth basin. Migration shares and the 500 km reach are illustrative rules, not a migration model. The simplified basin outlines leave thin gaps along shared edges; clicks there snap to the nearest basin. Kontur and Natural Earth populations differ by over 25% for a few countries (Syria, Moldova, Lebanon, Palestine, Eritrea, Cyprus, Bahrain), mostly because of refugee movements and disputed census figures.
10. **News scenarios are keyword matches.** Conflict surges need a headline that names infrastructure or the place, and a site nearby; topic searches (GDELT) take the first city or country a headline names, so a story about one place that mentions another can land in the wrong one. Earthquakes, storms and floods are placed by their own coordinates but sized by rules of thumb (magnitude, PAGER alert, wind speed). The Claude review and the human PR review are the filter. The three levels are rules of thumb on radius and damage, not forecasts. GDELT rate-limits busy IPs (one request per 5 s, longer bans after bursts); a refused search reuses the last cached answer.
11. **Road and rail detours are coarse.** The networks are Natural Earth's simplified 10 m roads and railways, snapped together where line ends lie within 3 km, so minor roads are missing, some joins are guessed, and some detours give up (counted as "no practical route") where a real one exists. Traffic is a gravity trip index between cities of 100,000+, not vehicle counts or freight tonnes; ferries, border closures and line capacity aren't modelled.
12. **Performance.** `power.geojson` (~8.5 MB, about 35k points) and `water_risk.geojson` (~7 MB) are the heaviest files. If load time matters, convert to vector tiles (PMTiles via tippecanoe), served statically with the `pmtiles` protocol.
13. **Information, health and food models are sketches.** Chip capacity comes from Wikipedia's fab list (wafers a month, converted to 300-mm equivalents; many plants lack a figure or node, phases are merged) and chip trade from country totals, so "who runs short" is the biggest buyers, not traced flows. Cloud regions are city points; losing one counts as losing all its zones. Outbreak arrival uses effective distance on the 2014 OpenFlights network plus land neighbours; hospital strain compares a peak-load rule of thumb with a third of each country's beds. Food uses FAOSTAT 2023 output and importer-reported trade for six items; a hit country feeds itself first, and stocks, substitutes and prices are not modelled. `fdep` (cereals imported) counts only wheat, maize and rice, so it overstates dependence where millet, sorghum, cassava or teff are staples (the Sahel, Ethiopia); `domains.json` now also has `fdep2` (all cereals plus starchy roots, from FAO food balance sheets), which the page does not use yet. `fdep2` ignores stock changes and is clamped to 0–1, so re-export hubs (Netherlands, Belgium, Portugal) read 1; FAO's balance sheets leave out Japan, Singapore, Sudan, Mali, Chad and a few others. Mines now have downstream buyers in `domains.json` `minerals` (BACI country-to-country iron ore and coal trade), but not mine-level ones.
14. **Submarine cable licence is unclear.** TeleGeography's current terms give CC BY-SA 4.0 only for references to its maps and screen captures and say the underlying databases are for subscribers; the earlier CC BY-NC-SA 3.0 statement this atlas relies on could not be found again in October 2026. Keep the cable layer non-commercial and credited, and check with TeleGeography before any commercial use.
