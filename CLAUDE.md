# Notes for Claude Code

- The app is one file: `site/index.html`. The map logic lives in the second `<script>` block. Read the README section "How the page works" before editing.
- Serve with `python -m http.server 8765 --directory site` (or `python3 tools/offline.py serve`, which also serves the offline store). Don't open it as `file://`, because `fetch()` of `data/` fails there.
- **Verify visual changes.** Run `python tools/screenshot.py` (needs `pip install playwright && playwright install chromium`) and look at `tools/shots/*.png`. Rendering problems such as misaligned glyphs or lattice artifacts only show up at fractional zooms, so check at least 1.5, 2.4, 3.4, 4.5 and 6. Software WebGL is slow, so allow 5–15 s per screenshot.
- `#debug` in the URL exposes the map as `window.__atlasMap`.
- MapLibre is pinned to 4.7.1. Expression gotcha: `["zoom"]` may only appear as the input of a top-level `interpolate` or `step`. Wrap per-feature logic inside the stops; don't multiply a zoom curve.
- Colours are CSS tokens on `:root`, redefined twice for dark mode (the media query and `[data-theme="dark"]`). If you add a layer colour, add the token in all three places and add a line to `repaint()`. Canvas icons (`ICONS`) are redrawn there too.
- **Don't edit `site/data/*` by hand.** Change the pipeline and rerun `pipeline/run_all.sh`. The raw inputs are described in `raw/README.md`. Step 5 (`pipeline/step5_defense_infra.py`: bases, airports, ports, data centres) downloads its own inputs; `--offline` rebuilds from `raw/infra/`.
- `site/data/live/` is generated by `pipeline/live/fetch_live.py` (run by `.github/workflows/pages.yml` every 3 h) and is gitignored. Run it locally to get live layers in dev.
- Satellite imagery: GIBS's `default` time differs between CDN edges, so tiles mix days. Always pin an explicit time (`gibsLatest()` reads the `layer-time-actual` header). A GIBS layer's max zoom equals its `Level` number in the tile matrix set.
- Offline backup: `tools/offline.py sync|status|serve`. The store (~120 GB: OSM planet, terrain, glyphs, NASA mosaics) lives in `~/atlas-offline`, never in the repo. `serve` is needed for pmtiles because it supports Range requests. Any new online tile service should get a local fallback in `offReady` or say in the README that it needs the internet. Test offline by blocking every non-localhost request in Playwright.
- Every data source must appear in `SOURCES` in `index.html` and in the README's sources list, with its licence. PeeringDB (AUP) is merged into `datacenters.geojson` only at deploy time by `pages.yml`, by the owner's choice; never commit a `--with-peeringdb` build.
- Scenario solver: the worker is the `<script type="text/plain" id="simWorker">` block (no DOM; runs in a Worker and in node `vm`). The river-basin model is the classic `<script id="simWater">` block (pure functions, globals shared with the main script). After changing either block, `energy_graph.json` or `basins.json`, run `node --test 'tests/*.test.mjs'` (quote the glob).
- `basins.json` is index-aligned with `water_risk.geojson`; rerun `step6_network_pop.py --only=water` after any step 4 change, or the client refuses to load it.
- `transport_graph.json` points into the parts of `roads.geojson` and `rail.geojson`; rerun `step6_network_pop.py --only=transport` when they or `labels.json` change (the client falls back to straight lines on a mismatch). The road/rail model is the `<script id="simTransport">` block, run in a worker with `#simTransportWorker`; tests in `tests/transport.test.mjs`.
- `site/data/scenarios_weekly.json` (the Scenarios panel's "This week's news" tab) is written by `pipeline/live/story_scenarios.py` and arrives through the weekly PR from `.github/workflows/scenarios-weekly.yml`; validate edits with `story_scenarios.py --check`. After changing `SIM_PRESETS` or ids in the data, run `node --test tests/presets.test.mjs`.
- Open tasks: see "Known issues" in the README.
